Protocol & Cryptographic Reference

Outrider speaks MCP protocol revision 2026-07-28 alongside legacy initialize handshakes on /mcp. Multi-round-trip (MRTR) quotes bind a session subject, bundle_id, and SHA-256 catalog item digests to a single-use quote_id with a Unix expiry, while authenticated RequestStateCodec tokens carry input_required capability probes and elicitation continuations without unverified client state.

Capability receipts ({receipt_id, subject, bundle_id, item_digests, max_calls, expires_at_unix}) are canonicalized with RFC 8785 JSON Canonicalization Scheme (JCS) and signed with the gateway's Ed25519 key (outrider-ed25519.pem), then encoded as URL-safe unpadded Base64 tokens. On tool invocation, Outrider verifies the Ed25519 signature strictly, checks bundle digest integrity and non-revocation, and decrements remaining_calls inside an atomic SQLite IMMEDIATE transaction.

CLEF evaluates persisted session handshakes and active probe runs through LiteRT-LM (litert-lm-rust 0.2.4) using JSON-schema constrained decoding across three question kinds: noul (boolean), choice (finite string options), and score (bounded integer min..max). Every evaluation records exact pick, input_tokens, output_tokens, latency_ms, and backend; option_scores is explicitly null because litert-lm-rust 0.2.4 does not expose option probability distributions.

On inbound proxy and gateway sockets, Outrider passively records TLS ClientHello bytes (client_hello), negotiated TLS parameters (negotiated_tls), raw HTTP header ordering (http_header_order), and MCP client capability configurations (mcp_request) in fingerprint_observations. Active sampling probes follow the operator's probe_policy (off, on-request, or auto) and store measured latency and structural compliance in probe_runs.

To inspect HTTPS traffic through Outrider, install the generated root CA in your platform trust store: on macOS run `sudo security add-trusted-cert -d -p ssl -p basic -k /Library/Keychains/System.keychain proxyfor-ca-cert.pem`; on Ubuntu/Debian copy proxyfor-ca-cert.pem to `/usr/local/share/ca-certificates/proxyfor.crt` and run `sudo update-ca-certificates`; on Windows run `certutil.exe -addstore root proxyfor-ca-cert.cer`. Full step-by-step instructions for macOS, Linux, Windows, iOS, Android, and Firefox are served at `/__proxyfor__/certificate/`.
